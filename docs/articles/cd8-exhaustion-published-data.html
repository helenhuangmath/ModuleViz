Abstract

This vignette demonstrates a reproducible ModuleViz workflow using published RNA-seq and CUT&Run data from memory and exhausted CD8 T cells. RNA-seq data define temporal modules along an ordered differentiation axis, and H3K27ac CUT&Run signal is aligned to those modules by gene.

1 Introduction

r Biocpkg("ModuleViz") can be used with an ordered biological axis even when the axis is not clock time. This vignette demonstrates that workflow on published CD8 T cell differentiation data.

The other vignette uses the bundled synthetic dataset so it runs offline. This one is the opposite: it walks through a complete, published, real analysis end to end, on data anyone can download.

We use two GEO series from the same study of histone modifications in memory and exhausted CD8 T cells (PubMed 40389726):

Accession Assay Samples What we use it for
GSE285248 RNA-seq 16 Defines the temporal modules
GSE285245 CUT&Run (H3K27ac, H3K27me3) 86 Chromatin layer aligned to those modules

The experiment. Naive P14 CD8 T cells were transferred into recipient mice infected with LCMV Armstrong, which resolves and yields memory cells (harvested day 30), or LCMV Clone 13, which persists and yields exhausted cells (harvested day 32). Spleens were profiled by RNA-seq and by CUT&Run for activating (H3K27ac, H3K4me3) and repressive (H3K27me3, H3K9me3) marks.

The trajectory. ModuleViz was built for time courses, but nothing in it requires the ordering variable to be wall-clock time. Here the ordered axis is a differentiation axis:

TN (naive)  ->  TMEM (memory)  ->  TEX (exhausted)

Any ordinal sample axis works the same way: differentiation stages, disease grades, dose levels, or developmental stages.

Chunks in this vignette are not evaluated at build time, because they download data from the NCBI FTP server. Every chunk is runnable as written — copy them in order, or run the whole thing at once with Rscript examples/validate_real_data.R from the package root, which executes this exact analysis plus 114 correctness assertions.

3 Build The Sample Metadata

ModuleViz needs one row per sample with a sample ID and a numeric ordering column. The GEO column names encode everything we need in the pattern <Infection>_P14_Day<d>_<assay>_Rep<n>_S<n>, so the metadata can be parsed straight out of them. Writing this as a function pays off later, because the CUT&Run tables follow exactly the same naming scheme.

```{r metadata} make_meta <- function(cols, assay) { infection <- sub(“P14.“,”“, cols) day <- as.integer(sub(”._Day([0-9]+)_.*“,”\1”, cols)) state <- c(Naive = “TN”, Arm = “TMEM”, Cl13 = “TEX”)[infection] data.table( SampleID = cols, State = factor(state, levels = c(“TN”, “TMEM”, “TEX”)), # the ordered differentiation axis handed to time_col StateOrder = unname(c(TN = 1, TMEM = 2, TEX = 3)[state]), # naive cells are the pre-infection baseline, so they sit at day 0 Day = ifelse(infection == “Naive”, 0L, day), Replicate = as.integer(sub(“.Rep([0-9]+).”, “\1”, cols)), Assay = assay ) }

rna_meta <- make_meta(rna_cols, “RNA”) rna_meta[, .N, by = .(State, Day)]

#> State Day N #> #> 1: TN 0 8 #> 2: TMEM 30 4 #> 3: TEX 32 4


`StateOrder` is the key column: it is what `time_col` will point at, and it is
what makes the modules come out ordered naive-high through exhaustion-high.

Note that there are **eight** naive samples, not four. Naive cells were profiled
twice, once alongside each infection, so they serve as the day-matched baseline
for both arms. That imbalance is fine — nothing in `ModuleViz` requires equal
group sizes.

# Select Differentially Expressed Genes

Real analyses do not cluster the whole transcriptome. Clustering 16,429 genes
would bury the interesting structure under thousands of flat, uninformative
profiles. We select the genes that actually move across the three states.

A vectorised one-way ANOVA across `TN` / `TMEM` / `TEX` is fast and needs no
extra packages. If you already have `DESeq2` or `edgeR` results for this
comparison, substitute them here — all that matters downstream is a set of gene
IDs and, optionally, a ranking statistic.

```{r deg}
log_rna <- log2(rna_mat + 1)

deg_anova <- function(x, grp) {
  grp <- factor(grp)
  n <- ncol(x); k <- nlevels(grp)
  grand <- rowMeans(x)
  ssb <- 0; ssw <- 0
  for (g in levels(grp)) {
    cols <- which(grp == g)
    mg   <- rowMeans(x[, cols, drop = FALSE])
    ssb  <- ssb + length(cols) * (mg - grand)^2
    ssw  <- ssw + rowSums((x[, cols, drop = FALSE] - mg)^2)
  }
  df1 <- k - 1; df2 <- n - k
  Fstat <- (ssb / df1) / (ssw / df2)
  Fstat[!is.finite(Fstat)] <- 0
  data.table(
    ID     = rownames(x),
    Fstat  = Fstat,
    pvalue = stats::pf(Fstat, df1, df2, lower.tail = FALSE),
    padj   = stats::p.adjust(stats::pf(Fstat, df1, df2, lower.tail = FALSE),
                             method = "BH")
  )
}

state_of <- rna_meta$State[match(colnames(log_rna), rna_meta$SampleID)]
deg <- deg_anova(log_rna, state_of)

mean_by <- function(s) rowMeans(log_rna[, state_of == s, drop = FALSE])
deg[, `:=`(
  log2FC_TMEM_vs_TN  = mean_by("TMEM") - mean_by("TN"),
  log2FC_TEX_vs_TN   = mean_by("TEX")  - mean_by("TN"),
  log2FC_TEX_vs_TMEM = mean_by("TEX")  - mean_by("TMEM"),
  baseMean           = rowMeans(rna_mat)
)]
deg[, maxAbsLFC := pmax(abs(log2FC_TMEM_vs_TN), abs(log2FC_TEX_vs_TN),
                        abs(log2FC_TEX_vs_TMEM))]

sig <- deg[padj < 0.01 & maxAbsLFC >= 1 & baseMean >= 10]
setorder(sig, -Fstat)
nrow(sig)
#> [1] 4176

4,176 genes pass. We keep the top 3,000 by ANOVA F so the vignette runs quickly; raise or drop the cap freely.

The elbow lands at k = 5, but we use k = 6. This is worth being explicit about, because it is the most common judgement call in this workflow.

At k = 5 there is no memory-peaking module at all: the TMEM-specific programme is absorbed into its neighbours, so the modules run naive -> naive -> naive -> exhausted -> exhausted. Since memory-versus-exhaustion is the comparison this study exists to make, k = 5 would hide the result. At k = 6 a module with a clear TMEM peak appears (Cluster4 below), and every module still has a stability above 0.9.

The elbow is a heuristic; a k that merges two biologically distinct programmes is worse than one that splits a module in two. If you want the figure itself to record the k you settled on, choose_k(..., chosen_k = K) draws it as a solid line beside the dashed elbow, and annotate_k = FALSE strips both markers for a bare curve.

# Draw The Heatmap

Three palettes are in play, and each is chosen for its job:

- `cluster_palette` — a **qualitative** palette for module identity (`"paired"`,
  `"set2"`, `"set3"`, `"okabe_ito"`, ...).
- `annotation_palette` — a qualitative palette for categorical metadata bars.
  `"set2"` is the default; use `"set3"` beyond eight levels.
- `zscore_palette` — a **continuous** scale for the matrix body: `"viridis"`
  (perceptually uniform and colour-blind safe) or `"rdbu"` (diverging). This
  walkthrough uses one scheme throughout; change the single argument to swap it.

```{r heatmap}

11 Add The CUT&Run Layer

Now the paired-omics question: does chromatin state track these expression modules?

The CUT&Run tables give peak coordinates but no gene symbol, so peaks have to be assigned to genes first. We map each peak to its nearest gene transcription start site, using the coordinates already present in the RNA annotation, and keep peaks within 25 kb.

```{r peak-mapping} gene_tss <- unique(rna_uniq[, .(Chr, TSS = ifelse(Strand == “+”, Start, End), Gene = Gene.Name)])

map_peaks_to_nearest_gene <- function(peaks, genes, max_dist = 25000) { out <- list() for (ch in intersect(unique(peaksChr), unique(genesChr))) { gg <- genes[Chr == ch][order(TSS)] pp <- peaks[Chr == ch] if (!nrow(gg) || !nrow(pp)) next i <- findInterval(ppMid, ggTSS) lo <- pmax(i, 1L); hi <- pmin(i + 1L, nrow(gg)) dlo <- abs(ppMid − ggTSS[lo]); dhi <- abs(ppMid − ggTSS[hi]) pick <- ifelse(dlo <= dhi, lo, hi) out[[length(out) + 1L]] <- data.table(peakN = pppeakN, Gene = ggGene[pick], dist = pmin(dlo, dhi)) } rbindlist(out)[dist <= max_dist] }


`dual_omics_heatmap()` recovers the gene from a secondary row ID using
`gene_of_secondary`, whose default is `sub("^.*_", "", id)` — everything after
the last underscore. So we name the rows `peak1243_Pdcd1` and the default just
works.

```{r load-cutrun}
load_cutrun <- function(path, mark) {
  tab   <- fread(path)
  scols <- grep(paste0("_", mark, "_Rep"), names(tab), value = TRUE)
  pk    <- tab[, .(peakN, Chr, Mid = as.integer((Start + End) / 2))]
  ann   <- map_peaks_to_nearest_gene(pk, gene_tss)
  tab   <- tab[peakN %in% ann$peakN]
  ann   <- ann[match(tab$peakN, peakN)]
  m     <- as.matrix(tab[, ..scols])
  rownames(m) <- paste0(ann$peakN, "_", ann$Gene)   # PeakID_SYMBOL
  list(mat = log2(m + 1), meta = make_meta(scols, mark), ann = ann)
}

12 Adapting This To Your Own Data

The only project-specific parts are steps 2 to 4. Everything from step 5 onward is generic. To reuse the workflow you need:

  1. A numeric feature-by-sample matrix with feature IDs as rownames.
  2. A metadata table with a sample ID column matching the matrix columns, and a numeric ordering column for time_col (real time, or an ordinal stage as here).
  3. Optionally, a group_col for a second factor such as genotype or treatment arm, which splits the heatmap columns and facets the line plot.
  4. Optionally, a secondary matrix whose rownames end in _<GeneSymbol>, or a custom gene_of_secondary function.
